# Marla 想法池

这里仅保存仍然开放、但尚未形成当前开发承诺的产品想法。已经实现、明确拒绝或被后续 Task 完整取代的条目不继续留在当前想法池；它们的决定、范围和证据由 Git 历史、对应 Task、ADR、规格与 `STATUS.md` 保存。

想法不是 Backlog，也不授权实现。只有项目所有者明确确认未来需要完成，或 Accepted ADR 已经确认方向后，才能进入 Backlog；被选为当前工作后仍需建立一个边界清楚的 Task。

## 状态定义

- `Captured`：值得保留，尚未系统验证或确认实施。
- `Accepted direction`：方向已有 Accepted ADR 或明确产品决定，但仍缺少产品决策、证据或 Task 范围。

`Priority: Unranked` 是正常状态。价值、成熟度和开发顺序不是同一件事。

## IDEA-001：按需上下文感知翻译

Status: Accepted direction

Priority: Unranked

Source: 用户讨论 + ADR-0003

Related: `ADR-0003-context-engine.md`、BL-005、`DATA_CONTRACTS.md`

### 一句话描述

只在用户触发翻译时，取得最少且有界的应用、附近文字或术语线索，帮助模型理解当前语境；不得把 Marla 变成持续观察屏幕的后台监控器。

### 用户价值

相同词语在终端、邮件、论文、代码和聊天中的含义与语气可能不同。短选区缺少主语、领域和专有名词时，适量语境可能降低术语误译和风格漂移。

### 当前边界

- 当前实现不把应用身份、窗口标题、附近文字或术语发送给 Provider。
- 只允许在明确翻译触发后构造短生命周期、有字符数与 TTL 上限的 `ContextSnapshot`。
- 应用分类只能是弱提示；用户显式术语应优先于自动证据。
- 获取失败必须直接退化为当前无上下文翻译，不能拖慢结果卡壳层出现。
- 默认不得持续截屏、后台 OCR、记录完整窗口或在日志中写入上下文正文。

### 进入开发的条件

1. 决定默认关闭还是开启，以及用户能看到和关闭什么。
2. 定义允许采集、禁止采集、清洗、最大字符数和 TTL。
3. 建立终端、网页、邮件、聊天和代码错误的无上下文/有上下文盲测。
4. 明确 Provider 不支持上下文时的降级。
5. 首个 Task 只验证一种证据源，不一次实现完整缓存与自动术语系统。

### 下一步

先完成隐私边界和离线质量评测，再决定是否从 BL-005 创建实现 Task。

## IDEA-004：单格式起步的文档翻译工作区

Status: Captured

Priority: Unranked

Source: 用户讨论

Related: IDEA-009

### 一句话描述

在不改变瞬时入口定位的前提下，增加用户显式打开的主工作区，从一种文档格式开始提供多页解析、翻译和对照阅读。

### 用户价值与边界

瞬时翻译适合短选区和小区域，不能高效处理整篇论文、合同或演示文稿。文档工作区应是第二种使用模式，不让主窗口成为日常翻译的必经入口，也不以“万能文档”作为首期范围。

### 主要风险

- PDF、DOCX、PPTX、XLSX 的解析和导出语义完全不同，范围容易失控。
- 多页任务需要队列、取消、进度、失败恢复和成本估算。
- 文档持久化会改变当前不保存用户内容的隐私模型。
- 保版式导出远比只读对照复杂，不能在同一首期承诺。

### 进入开发的条件

1. 由真实需求选择一个文件类型。
2. 决定首期是只读对照还是生成文件，不同时承诺保版式导出。
3. 明确文件和任务是否保存、保留多久、如何彻底删除。
4. 建立独立产品规格和必要 ADR。

### 下一步

收集真实使用中最常见的第一个文件格式；没有明确样本和输出目标前不提升。

## IDEA-005：用户可控术语表

Status: Captured

Priority: Unranked

Source: 上下文讨论

Related: IDEA-001、ADR-0003

### 一句话描述

允许用户明确保存术语、固定译法和语言方向，使产品名、技术名词、人名及团队表达在翻译中保持一致。

### 当前判断

显式术语比自动猜测更可控，也是未来上下文增强中置信度最高的证据。首期应本地、手动、可查看和可删除，不从翻译历史自动学习。

### 风险与未知

- 同一术语在不同语境可能需要不同译法。
- 长术语表会增加 token、延迟和 Provider 遵循不确定性。
- 专用翻译 Provider 未必支持与通用模型相同的术语合同。
- 冲突、大小写、词形变化与语言方向需要明确优先级。

### 进入开发的条件

1. 定义最小数据模型、条数/字符上限和删除语义。
2. 决定只支持精确手动术语，还是同时包含应用/领域范围；首期优先前者。
3. 用固定样本证明当前 Provider 能稳定遵守术语。
4. 明确本地存储、导出与隐私说明。

### 下一步

与 IDEA-001 的质量评测共用样本，但若实施则建立独立窄 Task。

## IDEA-006：持久翻译历史、收藏与恢复

Status: Captured

Priority: Unranked

Source: 产品规划

### 一句话描述

在用户明确选择后，让内容跨退出保存，用于查找最近翻译、收藏重要结果或恢复误关内容。

### 当前事实

Marla 已有有界、仅内存、退出即清空的最近翻译；这不是持久历史。持久化原文、译文、应用来源或截图会改变当前数据生命周期，不能由现有最近记录自动扩展。

### 可选最小形态

- 只保存用户明确收藏的条目；
- 默认关闭且有保留上限的本地历史；
- 仅增加会话内撤销关闭，不跨重启保存。

### 进入开发的条件

项目所有者先从上述形态选择一个，并明确加密、保留时长、搜索、删除、导出及截图是否永不保存。云同步与账号不与首期捆绑。

### 下一步

等待真实使用证明误关或再次查找是高频问题。

## IDEA-008：更多瞬时翻译入口

Status: Captured

Priority: Unranked

Source: 用户讨论

### 一句话描述

只有当现有划词、截图和 Quick Input 无法顺畅覆盖某个真实工作流时，再增加一个用户明确触发的入口。

### 候选

| 候选 | 可能价值 | 主要风险 |
| --- | --- | --- |
| macOS Service / PopClip 直传 | 绕开特定应用的选区兼容问题 | 安装与来源校验、应用支持不一致 |
| 显式翻译当前剪贴板 | 适配无法读取的选区 | 误传旧的敏感剪贴板 |
| 拖文字或图片到菜单栏图标 | 意图清楚，适合图片 | 拖动成本和文件生命周期 |
| Finder Quick Action | 文档入口自然 | 容易扩张为 IDEA-004 |

纯悬停和 Force Touch 不在候选中：前者意图弱且可能持续读取内容，后者已在真实试用中证明不可靠并删除。

### 进入开发的条件

记录一个现有三入口确实不顺手或失败的具体场景，一次只选择一个入口，并定义来源、长度限制、隐私、取消与可测成功标准。

### 下一步

不预先实现入口列表；由真实失败事件触发评估。

## IDEA-009：本地 OCR / VLM 能力分档

Status: Captured

Priority: Unranked

Source: OCR 模型讨论

### 一句话描述

未来只有在目标 Mac 上找到明显优于 Vision、又满足资源与分发边界的模型时，才增加可下载的本地结构 OCR 档位。

### 当前事实

当前已经形成清楚分层：Vision 是默认、本地、纯文本路径；用户明确选择 GLM-OCR 时上传所选截图并得到结构化结果，失败可见地退回 Vision。参数量和权重大小不能证明某个本地模型适合瞬时体验。

### 必测指标

模型文件大小、冷/热启动、首结果与完整结果时间、常驻/峰值内存、能耗、卸载回收、表格/代码/混排结构质量、许可和 Apple Silicon 兼容性。

### 进入开发的条件

候选必须在目标 Mac 上同时证明：相对 Vision 有明确质量增益、冷启动可接受、峰值低于 1GB、可合法分发且上传/本地语义对用户清楚。否则保持 Vision + 可选云端。

### 下一步

不打包本地模型；只有出现可信候选或文档工作区需求后才建立 benchmark Task。
