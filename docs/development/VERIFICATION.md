# 当前开发基线验证记录

这里记录当前开发基线已经实现、需要项目所有者在真实环境中验收或测量的工作及其最终结果。Marla 当前处于无发布版本的孵化期；这些证据可以被未来发布准备引用，但本文件本身不是发布合同。

它不是产品想法，也不是已确认的未来功能 Backlog。验证项通常不改产品范围；如果验证发现可复现缺陷，再从验证项创建一个独立的 `TASK-xxx`。

## 状态定义

- `Ready`：范围和环境条件明确，可以开始验证。
- `In progress`：正在进行真实环境验证或测量。
- `Blocked`：缺少目标设备、权限、账号或项目所有者决定。
- `Complete`：当前固定版本已有足够证据。

### RV-005：GLM-OCR 真实凭据成功路径

- 在固定签名 `artifacts/Marla_dev.app` 的 OCR 设置 SecureField 中，由项目所有者自行输入 GLM Key，保存后选择云端 GLM-OCR。

- 证据只记录成功/失败、脱敏时延范围与结构类型统计；不记录 Key、Authorization Header、完整截图、Provider 账号或识别正文。
- 该验证项未完成不重新打开已完成的 `TASK-033`；若真实调用发现可复现代码缺陷，再创建独立修复 Task。

### RV-002：截图裁剪与权限持久化

- 验证单屏、Retina、多屏、负坐标和混合缩放下，框选区域与 Vision 实际输入一致。
- 验证悬停弹层、播放中视频、真实 `Esc`、右键、无效区域、捕获失败和空 OCR 路径。
- 在稳定签名固定 App 上复验 Screen Recording 权限及重启后的持久性。
- 不把用户截图写入仓库；临时诊断产物必须显式启用并清理。
- 2026-08-18，项目所有者明确回报 `RV-002` 通过。该结论关闭本项定义的真实裁剪、冻结画面、取消路径、代表性显示器布局与 TCC 持久性验证；未提供也未补写显示器型号、排列参数或用户截图。TASK-022 的日/韩/中/英固定开发 App OCR 与语言路由证据仍需独立判断，不由本结论自动扩写。

### RV-003：UI 延迟与内存预算

- UI 壳层 P95 约 150ms 内，Rust 回调到 Swift 可见 delta P95 低于 50ms。
- 空闲低于 150MB、常规低于 300MB、Vision 期间低于 500MB，任何验收场景低于 1GB。
- 记录样本数量、短/长文本、冷/热启动、显示器环境、工具和结果位置。
- 2026-08-18 在 Apple M4、macOS 26.6.1 的固定签名 `artifacts/Marla_dev.app` 上完成 30 组本地样本。每组使用独立 Release 进程；入口计时从 fixture 入口到面板完成布局、显示提交且可见，P50/P95/max 为 131.869/145.947/149.332ms；delta 计时从 Rust callback 解码后到对应 `.streaming` 会话完成主线程布局与显示提交，P50/P95/max 为 35.068/43.957/44.074ms。
- delta 样本只连接 `127.0.0.1` SSE fixture，不包含外部网络 TTFT、完整响应时间或吞吐；原始临时证据 `/private/tmp/marla-rv003-latency.jsonl` 共 60 行，只含 `schemaVersion`、metric 名称和纳秒时长，不含凭据或内容。
- RSS 证据：长期运行固定 App 空闲 129,120 KiB（约 126.1 MiB）；`markdown-completed` 冷进程最大 135,168,000 bytes（约 128.9 MiB）；真实 ScreenCaptureKit 全显示器冻结/框选 fixture 最大 341,147,648 bytes（约 325.3 MiB）；沙盒外 2400×1600 Vision accurate OCR 探针最大 154,451,968 bytes（约 147.3 MiB，OCR 约 0.337s）。后两条分别测量冻结/框选与 Vision，未把未发生的同时峰值伪写为实测组合。
- 本项关闭预算测量；旧 `0.1.0` 草案中“动画期间主观流畅”和“关闭会话后无持续增长”没有被预算结果替代，保留为历史未验证项，但不再构成活动发布阻塞。

## 工作规则

1. 验证项完成后更新本文件和 `STATUS.md`，不把未验证事实写成已完成。
2. 验证发现的可复现代码缺陷，创建或启动一个独立 `TASK-xxx`；不要直接把修复混入验证项。
3. 新产品能力先进入 `backlog/IDEAS.md`，经项目所有者确认后进入 `backlog/BACKLOG.md`。
