# 当前版本验证队列

这里记录当前版本已经实现、但仍需要项目所有者在真实环境中验收或测量的工作。

它不是产品想法，也不是已确认的未来功能 Backlog。验证项通常不改产品范围；如果验证发现可复现缺陷，再从验证项创建一个独立的 `TASK-xxx`。

## 状态定义

- `Ready`：范围和环境条件明确，可以开始验证。
- `In progress`：正在进行真实环境验证或测量。
- `Blocked`：缺少目标设备、权限、账号或项目所有者决定。
- `Complete`：当前固定版本已有足够证据。

### RV-002：截图裁剪与权限持久化

- 验证单屏、Retina、多屏、负坐标和混合缩放下，框选区域与 Vision 实际输入一致。
- 验证悬停弹层、播放中视频、真实 `Esc`、右键、无效区域、捕获失败和空 OCR 路径。
- 在稳定签名固定 App 上复验 Screen Recording 权限及重启后的持久性。
- 不把用户截图写入仓库；临时诊断产物必须显式启用并清理。

### RV-003：UI 延迟与内存预算

- UI 壳层 P95 约 150ms 内，Rust 回调到 Swift 可见 delta P95 低于 50ms。
- 空闲低于 150MB、常规低于 300MB、Vision 期间低于 500MB，任何验收场景低于 1GB。
- 记录样本数量、短/长文本、冷/热启动、显示器环境、工具和结果位置。

## 工作规则

1. 验证项完成后更新本文件和 `STATUS.md`，不把未验证事实写成已完成。
2. 验证发现的可复现代码缺陷，创建或启动一个独立 `TASK-xxx`；不要直接把修复混入验证项。
3. 新产品能力先进入 `backlog/IDEAS.md`，经项目所有者确认后进入 `backlog/BACKLOG.md`。
