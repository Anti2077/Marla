# Task 施工单

Task 是 Agent 的直接施工依据。项目同一时刻最多只有一个 `Active` Task；讨论未来功能不自动创建 Task。

## 文件命名

```text
TASK-001-short-name.md
```

编号一经使用不回收。标题使用可读短语，不使用版本号代替工作内容。

## 生命周期

- `Draft`：正在补齐范围，禁止实现。
- `Ready`：范围和验收明确，等待项目所有者启动。
- `Active`：当前唯一允许实施的任务。
- `Blocked`：存在具体外部阻塞，记录恢复条件。
- `Done`：代码、测试和文档均已验证。
- `Cancelled`：明确停止，保留原因。

## 使用规则

- 一个 Task 只追求一个用户可感知结果或一个明确验证结果。
- 写清 `In Scope`、`Out of Scope`，防止 Agent 顺手扩张范围。
- `Required Reading` 只列真正相关文档，避免每次吞下整个项目历史。
- 验收必须可观察；“体验更好”“代码更优雅”不能单独作为标准。
- 实现中发现新想法时写入 `backlog/IDEAS.md`，不扩张当前 Task。
- 实现中发现必须追加的工作，先报告并由项目所有者决定是更新当前 Task 还是进入 Backlog。
